## 1. Новый экран `lib/presentation/screens/course_screen.dart`

Образец структуры и отступов — `lib/presentation/screens/sprint_screen.dart`
(`SingleChildScrollView` + `padding: EdgeInsets.all(24)` + `Center` +
`ConstrainedBox(maxWidth: 900)` + колонка `SectionCard`-ов, а сверху
`BlocBuilder` со `switch` по `status`: loading → `CircularProgressIndicator`,
failure → `ErrorPane`, ready → тело). Повтори этот каркас.

Тело сверху вниз:

### а) Карточки активных направлений

Одна карточка на направление, в порядке `order`. В карточке:
- имя направления крупно; справа меню (`PopupMenuButton`): переименовать,
  категории, горизонт, заметка, пауза, закрыть направление, удалить;
- **лестница одной строкой**: `ladderProgress(done, total)` («веха 3 из 7»)
  плюс полоска сегментов — закрытые залиты `colorScheme.primary`, открытые —
  `colorScheme.surfaceContainerHighest`. Это и есть визуальная дистанция,
  делай её заметной;
- строка следующей вехи: `→ <название nextOpen>`; если лестница пройдена —
  текст «лестница пройдена»;
- три мелкие подписи в ряд: темп (`paceLabel` / `noPace`), прогноз
  (`etaLabel` от `directionEta`, формат даты — `dateHuman` из
  `lib/data/markdown_codec.dart`), доля внимания за 30 дней в процентах;
- тап по карточке разворачивает **лестницу вех** (состояние «какая карточка
  раскрыта» держи в `State` экрана, как `_openDay` в `sprint_screen.dart`).

### б) Лестница вех (в раскрытой карточке)

`ReorderableListView` (`shrinkWrap: true`, `physics:
NeverScrollableScrollPhysics()`) по вехам направления:
- чекбокс закрытия: открытая → `closeMilestone(id, sprintId(logicalDate(
  DateTime.now())), DateTime.now())`; закрытая → `reopenMilestone(id)`.
  `sprintId` и `logicalDate` бери из `markdown_codec.dart` /
  `pomo_session.dart`, не пересчитывай неделю сам;
- закрытая веха — зачёркнутый текст приглушённым цветом плюс id недели
  закрытия справа мелко;
- перетаскивание вызывает `reorderMilestones`;
- долгий тап / иконка — переименовать, удалить (с подтверждением);
- снизу поле «Добавить веху» + кнопка, `Enter` тоже добавляет.

Если направлений нет вообще — пустое состояние с текстом из строк и кнопкой
«Добавить направление».

Если активных направлений больше 4 — под карточками мягкая подсказка
`tooManyDirections(n)` в цвете `colorScheme.tertiary`, без блокировок.

### в) Секции «На паузе» и «Закрытые»

Свёрнутые по умолчанию (`ExpansionTile` или та же механика, что у
сворачиваемых групп в `lib/presentation/screens/tasks_screen.dart` — посмотри,
как там сделано, и не плоди второй способ). Внутри — компактные строки с
именем и прогрессом лестницы, в меню — «Вернуть в работу».

### г) Лента закрытий

`SectionCard` с горизонтально прокручиваемой сеткой за последние 26 недель:
- строки — активные направления (плюс строка «вне направлений», если такие
  закрытия есть), колонки — недели слева направо, свежая справа;
- ячейка: закрытая веха — залитый квадратик `primary` с тултипом (название
  вехи + id недели); пусто — контур `outlineVariant`. Пустые недели показывай
  честно, ничего не прячь;
- под сеткой — подписи месяцев по колонкам, если влезают.
Данные — из `closuresByWeek`. Ширину ячеек считай так, чтобы на узком экране
(<600) сетка прокручивалась, а не ломала верстку.
Стрика («N дней подряд») НЕ делать: проект намеренно от неё отказался, лента
это летопись, а не цепочка, которую страшно порвать.

### д) Бюджет внимания

`SectionCard`: горизонтальные полосы по направлениям — доля помидоров за
последние 30 дней (`pomosByDirection` по журналу). Для каждой строки: имя,
полоса, `N 🍅 · X%`. Последняя строка — «вне направлений». Рядом с именем
покажи объявленный приоритет (`#1`, `#2`, … по `order`), чтобы расхождение
«говорю №1 — трачу 12%» било в глаза.

Журнал за 30 дней бери через `JournalCubit` / `StatsCubit`, если там уже есть
готовый диапазон; если нет — добавь в `DirectionsCubit` загрузку последних 30
дней через `JournalRepository` (передай репозиторий в конструктор кубита) и
держи их в состоянии. Второй запрос того же диапазона на каждый build
недопустим.
