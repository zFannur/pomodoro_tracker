## 1. PomoTask — план старта и переносы

Новые поля (все с дефолтами, в `copyWith` и `props`):

| Поле | Тип | JSON | Смысл |
|---|---|---|---|
| `firstStep` | `String` = `''` | `fs` | действие ≤5 мин; оно же «то» в плане «если — то» |
| `cue` | `String` = `''` | `cue` | ситуация «когда…» |
| `cueAt` | `String` = `''` | `cueAt` | время напоминания `HH:mm`, пусто — без напоминания |
| `deferrals` | `int` = `0` | `df` | счётчик переносов (растит P06) |

В `copyWith` для строк достаточно `String?` (пустая строка = очистить).

## 2. Один разбор задачи вместо двух

В `json_data_repository.dart` задача разбирается в двух местах: метод `_taskFrom`
и статический `_Doc._taskList`. Оставь одну статическую функцию разбора
(`_taskFromJson(Map<String, dynamic>)`), используй её в обоих местах, второе удали.
Поведение по старым полям не должно измениться (сравни обе версии построчно,
перенеси все отличия — например `clamp` минут).

## 3. PomoSession — id задачи

Поле `taskId` (`String` = `''`, JSON `tid`, опускать пустое). Нужно для метрик
«по какой задаче был помидор» (сессии сейчас знают только текст задачи).

- `TasksCubit._writeHistory` получает `String taskId = ''` и кладёт его в сессию.
- `completeFromTimer` передаёт `current?.id ?? ''`, `markDone` — id отмечаемой задачи.
- Ручные записи без задачи — пусто.

## 4. Direction — «Зачем»

Поле `why` (`String` = `''`, JSON `why`). Ценность направления в терминах ACT.

## 5. Слияние

Поля записей по id уже сливаются версией победителя — код слияния не трогай,
но добавь тест (п. 6), что новые поля переживают `mergeData`.
