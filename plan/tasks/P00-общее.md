# P00 — Общее для всех задач P01–P12

Прочитай этот файл и `plan/ПРОКРАСТИНАЦИЯ.md` целиком перед любой задачей P.
Там сценарии, причины/способы с окончательными текстами, формулы метрик, формат
данных и порядок задач. Задача P-файла — ЧТО и ГДЕ сделать; ПОЧЕМУ — в обзоре.

## Предусловие

Незакоммиченная работа по канбану (`kanban.dart`, `kanban_board.dart`, правки в
`sprint.dart`, `sprint_cubit.dart`, `tasks_cubit.dart`, `json_data_repository.dart`,
`data_merge.dart`, `timer_screen.dart`, `settings_dialog.dart`, `strings.dart`) должна
быть закоммичена ДО P01. Проверь `git status`: если эти файлы изменены — остановись
и скажи пользователю.

## Проект

Flutter 3.44 / Dart 3.12, Windows + Android. `flutter_bloc` (Cubit), `equatable`,
`fpdart` (`Either<Failure, T>` на границе репозиториев), `clock` (время в тестах —
`clock.now()`, не `DateTime.now()`, в новом коде), `http` (уже есть).

Слои:
- `lib/domain/entities/` — сущности на Equatable, чистые функции рядом с ними.
- `lib/domain/repositories.dart` — интерфейсы.
- `lib/data/json_data_repository.dart` — истина в `data.json`, все записи внутри
  `_serial`, `_Doc.encode/decode`, надгробия через `_Doc.ids()` до/после записи.
- `lib/data/data_merge.dart` — чистое слияние двух снимков для синка.
- `lib/data/markdown_codec.dart` — зеркала в Obsidian (только запись; парсеры — для миграции).
- `lib/presentation/cubits/`, `screens/`, `widgets/`.
- `lib/main.dart` — вся проводка кубитов и колбэков.

## Правила кода

- Комментарии и doc-строки — по-русски, коротко, объясняют ПОЧЕМУ.
- Все тексты UI — только в `lib/app/strings.dart` через `_t('рус', 'eng')`. Тексты
  причин и способов — дословно из обзора §4.
- Цвета — только из `Theme.of(context).colorScheme` / `lib/app/theme.dart`.
- Никаких новых зависимостей в `pubspec.yaml` (кроме случаев, явно названных в задаче).
- Минимум абстракций: никаких интерфейсов с одной реализацией, кроме репозиториев
  (так устроен проект). Повторяй существующие паттерны соседних файлов.
- Новое поле в JSON — короткий ключ, опускается, когда пустое/ноль/false.
  Старый data.json без поля читается без ошибок (тест обязателен).
- Не правь существующие тесты, кроме случаев, когда задача прямо меняет поведение;
  тогда объясни в отчёте, какой тест и почему.
- `test/screen_fakes.dart` — общие фейки для тестов экранов. Новый кубит в дереве
  провайдеров → добавь его в фейки, иначе упадут тесты экранов.

## Ловушки проекта (уже стоили багов — см. BUGS.md)

1. **Снимок поверх свежих данных.** `saveDay` и `saveSprint` пишут объект целиком.
   Поля, которыми владеют P-методы (`e`, `ck`, `ips` у дня; `exp`, `ai` у спринта),
   `saveDay`/`saveSprint` обязаны брать из хранимого документа, а не из снимка.
2. **Логический день** — с 05:00 (`dayStartHour`, `logicalDate`). Эпизод в 00:30
   относится к вчерашнему дню.
3. **Слияние не знает новых ключей.** `_mergeDays` пишет `{...w, 's':…, 'n':…}`:
   новый список внутри дня без явной строки слияния молча теряет данные второго
   устройства.
4. **`_purge`** чистит удалённые id только в перечисленных списках — новый список
   с id добавь туда же.
5. **Индексы задач устаревают** — ищи задачу по id или `todoIndexOf` в момент действия.
6. **Два места разбора задач** в `json_data_repository.dart` (`_taskFrom` и
   `_Doc._taskList`) — P01 сводит их в одно.
