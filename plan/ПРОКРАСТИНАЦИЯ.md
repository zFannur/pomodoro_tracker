# Прокрастинация: система самонаблюдения внутри таймера

Статус: план. Кода нет. 2026-11-04. Задачи для исполнителей — `plan/tasks/P00…P14`.
Текст справки и путь внедрения — `plan/help/СПРАВКА.md`. Макеты — `plan/design/макеты.html`.

Цикл как у Moa (Lee et al. 2025, пилотное RCT): **сигнал → причина → способ →
проверка**. Приложение само ловит момент откладывания, ты одним тапом
называешь причину, оно предлагает один способ с действием в один клик,
а через неделю само считает, сработало ли. ИИ (DeepSeek) не ведёт
свободный разговор: он заполняет три фиксированных места в сценарии.

Проверка исследований — в конце файла (§11).

---

## 1. Принципы (по ним проверять каждую задачу)

1. **≤ 1 минуты ручного ввода в день.** Всё, что можно посчитать, считается
   само: задержки, переносы, отвлечения, успех способа.
2. **Одна точка входа на каждое действие.** Причину отмечаешь только в
   «Листе эпизода». Эксперимент создаёшь только в «Разборе». Самочувствие —
   только в «Карточке дня». Остальные экраны их показывают, но не правят.
3. **Ничего модального без просьбы.** Сигналы — это чип, баннер или
   уведомление. Окно открывается только по тапу. Исключение — уже
   существующий «На чём встал?».
4. **Без ИИ работает всё.** ИИ улучшает три места, у каждого есть
   запасной вариант на правилах.
5. **Без диагнозов и оценок.** Тексты не говорят «ты прокрастинируешь».
   Говорят «что мешает начать?».
6. **Сначала неделя наблюдения.** Иначе сравнивать не с чем.

## 2. Новые понятия

| Понятие | Что это | Где живёт |
|---|---|---|
| **Эпизод** | Одна запись «не начинаю / отвлёкся / остановился / перенёс». Источник, задача, причина (по желанию), выбранный способ, мысль | `days[дата].e` в data.json |
| **Причина** | Одна из 7, фиксированный список (§4) | поле эпизода |
| **Способ** | Один из 9 приёмов КПТ / ACT / поведенческой активации / «если — то» (§4) | константы в коде + поле эпизода |
| **Успех способа** | Через ≤15 мин после эпизода начат или идёт засчитанный помидор ≥5 мин. Считается из журнала, не хранится | вычисление |
| **Первый шаг** | Действие ≤5 мин у задачи. Он же «то» в плане «если — то» | поле задачи `fs` |
| **Когда** | Ситуация для «если — то» и, по желанию, время напоминания | поля задачи `cue`, `cueAt` |
| **Переносы** | Сколько раз задачу откладывали, когда срок уже наступил | поле задачи `df` |
| **Разгон** | Помидор на 10 минут, который по окончании не обрывается, а переходит в Flowtime | режим таймера |
| **Самочувствие** | Сон, энергия (утром), день (вечером), 1–5 | `days[дата].ck` |
| **Эксперимент недели** | Гипотеза + способ + метрика + было/стало + вердикт | `sprints[неделя].exp` |
| **Шкала IPS** | 9 вопросов раз в месяц, самоотчёт | `days[дата].ips` |
| **Зачем** | Ценность направления (ACT), одна строка | поле направления `why` |
| **Неделя наблюдения** | Самая ранняя неделя с эпизодами. Способы не предлагаются (есть кнопка «всё равно помочь») | вычисление |

## 3. Сценарии работы

### 3.1 Первая неделя — наблюдение

Ничего не настраиваешь. Работаешь как обычно. Приложение ловит сигналы (§3.4–3.7),
ты на них отвечаешь одним тапом: причина. Способы не предлагаются, сверху
листа строка «Неделя наблюдения — просто отмечаем». Если совсем застрял —
«Всё равно помочь →» открывает способы.

В понедельник второй недели «Разбор» показывает первую картину: сколько
эпизодов, какие причины, задержки старта. Предлагает первый эксперимент.

### 3.2 Утро (≤ 30 секунд)

На таймере над карточкой СЕЙЧАС стоит **Карточка дня**:

```
┌ Доброе утро ─────────────────────────────── ✕ ┐
│ Сон      ○ ○ ○ ● ○        Энергия  ○ ○ ● ○ ○  │
│ Вчера 🐸 не сдвинулась. Так бывает.           │
│ [Что помешало?]  [Первый шаг для 🐸]          │
│ ▸ Когда сяду после завтрака → открою api.dart │
└───────────────────────────────────────────────┘
```

- Две строки точек: тап — оценка сохранена. Обе заполнены — строка уходит.
- Строка «Вчера…» появляется, только если вчера 🐸 была, но помидора по ней
  не было, или было ≥2 переноса. Текст без оценок (самопрощение снижает
  будущую прокрастинацию — Wohl, Pychyl, Bennett 2010).
- Последняя строка — план «если — то» сегодняшней 🐸. Повторение плана —
  главный усилитель эффекта (Sheeran, Listrom, Gollwitzer 2024).
- Когда всё заполнено и закрыто — карточки нет. После 17:00 на её месте
  строка «Как прошёл день? ○○○○○».

### 3.3 Старт задачи

Карточка СЕЙЧАС показывает под названием первый шаг:

```
            С Е Й Ч А С
   🐸 Подключить Stripe webhook   [оплата]
   ▸ Открыть dashboard → Webhooks
   Бот → Первый платёж от живого юзера
```

Space — старт как обычно. Если первого шага нет — строки нет. Добавить можно
в редакторе задачи или из листа эпизода.

### 3.4 Сигнал: не начинаю (простой)

Таймер стоит, в «Сегодня» есть задачи, простой ≥ 10 минут.

- Подсказка под кнопками (сейчас просто текст) превращается в чип:
  `Застрял? Что мешает начать →`. Тап — Лист эпизода (источник «простой»).
- **Windows:** если при этом ты за компьютером (был ввод за последнюю
  минуту) и сейчас окно одной из сессий (если расписание задано), через 15 минут
  простоя приходит одно уведомление «15 минут без помидора. Что мешает
  начать „Подключить Stripe webhook“?». Одно на один простой. В настройках
  выключается.

### 3.5 Сигнал: отвлёкся во время помидора (Windows)

Помидор идёт, на переднем плане приложение или вкладка, помеченные «отвлечение»
(пометка уже есть на экране Активности), ≥ 60 с подряд.

- Тихо создаётся эпизод (источник «отвлечение», имя окна).
- Уведомление: «YouTube во время помидора». Одно на помидор.
- На экране таймера появляется чип `Отвлёкся на YouTube — отметить причину`.
  Не ответил — эпизод остаётся без причины, это нормально.

### 3.6 Сигнал: остановил помидор раньше

Существующее окно «На чём встал?» получает строку чипов «Почему остановился»
(те же 7 причин + «доделал»). Ничего не выбрал — эпизода нет, только заметка.
Выбрал причину — эпизод (источник «стоп»). Способ не предлагается: в момент
остановки он не нужен. Причина пойдёт в разбор.

### 3.7 Сигнал: перенёс задачу

Перенос считается, только когда **срок уже наступил**: из «Сегодня» в
планировщик или из корзины «Срок» дальше. Разбор «Входящих» по корзинам — это
планирование, не перенос. «Пережила ночь в „Сегодня“» не считаем: вечером часто
собирают завтрашний день прямо там.

Отдельный сигнал — **🐸 не тронута за день**: при смене дня, если по лягушке
не было ни одного помидора, у неё +1 перенос и тихий эпизод «🐸». Его утром
показывает Карточка дня.

- Счётчик задачи +1, тихий эпизод (источник «перенос»).
- С третьего переноса на строке задачи бейдж `↻3`, снекбар:
  «Третий перенос. Разобрать, что мешает?» [Разобрать].

### 3.8 Сигнал: сам понял, что не идёт

Кнопка `Не идёт` рядом со Стартом (иконка + подпись на широком экране).
Открывает Лист эпизода (источник «вручную»).

### 3.9 Лист эпизода — центральный сценарий

Нижний лист на телефоне, диалог 460px на Windows. Три шага, каждый ≤ 10 секунд.

```
Шаг 1 — Что мешает?            «Подключить Stripe webhook»
 [Непонятно, с чего начать] [Слишком большая] [Скучно]
 [Боюсь сделать плохо] [Нет сил] [Не вижу смысла] [Отвлекли]
 Мысль (по желанию): ___________________________________
                                          [Только отметить]

Шаг 2 — Попробуй                      (после тапа по причине)
 ┌──────────────────────────────────────────────┐
 │ Первый шаг на 5 минут                         │
 │ Самое первое физическое действие:             │
 │ [Открыть dashboard Stripe → Webhooks____] ✨  │
 │                     [Сохранить и разгон 10 мин]│
 └──────────────────────────────────────────────┘
 Другой способ: [Только 10 минут] [Если — то] [Уменьшить]
 Помогало тебе: 4 из 5 раз

Шаг 3 — нет экрана. Таймер стартует, лист закрывается.
```

- «Только отметить» — эпизод с причиной, без способа.
- Рекомендованный способ — лучший по твоей личной статистике для этой
  причины (§4.3). Во время эксперимента недели первым идёт способ эксперимента.
- ✨ — ИИ предлагает 3 первых шага (если ключ задан). Без ключа кнопки нет.
- «Помогало тебе: 4 из 5» — успех способа по журналу. Меньше 3 попыток — строки нет.
- Причина «Отвлекли» — не прокрастинация: способы «Убрать раздражитель» и
  «Если — то», без подсчёта в разборе причин избегания.

### 3.10 Вечер (5 секунд)

После 17:00 в Карточке дня: «Как прошёл день? ○○○○○». Не нажал — ничего.

### 3.11 Понедельник — разбор недели (5 минут)

Вкладка **Разбор** (бывшая «Активность»), раздел «Неделя»:

1. Четыре плитки: первый помидор / простой / 🐸 первой / переносы (+ отвлечения
   на Windows), у каждой Δ к прошлой неделе и к неделе наблюдения.
2. Причины недели — полосы. У каждой причины — способ, который помогал лучше.
3. Самочувствие → дела: «Дни со сном ≥4: простой 6 мин. Со сном ≤2: 18 мин».
   Только когда в каждой группе ≥3 дня за 4 недели.
4. Итог эксперимента прошлой недели: было/стало, вердикт (авто, можно
   поправить). Работает — способ получает отметку «твой» и идёт первым.
5. Новый эксперимент: предложение (ИИ или правило) → [Взять] / [Свой] / [Пропустить].
6. ✨ Разбор от ИИ: 2–3 предложения и до трёх закономерностей. Кешируется в
   спринт и уходит в зеркало Obsidian.

Спринт показывает текущий эксперимент маленькой карточкой (только просмотр).

### 3.12 Раз в месяц — шкала (1 минута)

В «Разборе» в первую неделю месяца, если шкалы в этом месяце не было, —
карточка «Шкала откладывания, 9 вопросов». История баллов — линия.
Это контроль самоотчётом поверх объективных метрик.

## 4. Причины и способы

### 4.1 Причины

| id | Чип (RU / EN) | Откуда |
|---|---|---|
| `unclear` | Непонятно, с чего начать / Not sure where to start | Pychyl: неопределённость, нет структуры |
| `big` | Слишком большая / Too big | Pychyl: сложно, фрустрирует |
| `boring` | Скучно / Boring | Pychyl: скучно, нет награды |
| `perfect` | Боюсь сделать плохо / Afraid it won't be good | страх неудачи, перфекционизм (Rozental iCBT) |
| `tired` | Нет сил / No energy | состояние, не задача |
| `pointless` | Не вижу смысла / Don't see the point | Pychyl: нет личного смысла; ACT ценности |
| `external` | Отвлекли / Interrupted | внешнее, не избегание |

Плюс для стопа: `finished` — «Доделал / Finished» (не эпизод).

### 4.2 Способы

Тексты окончательные — исполнитель переносит их в `strings.dart` как есть.

| id | Метод | Для причин | Заголовок | Текст | Действие |
|---|---|---|---|---|---|
| `first_step` | поведенческая активация | unclear, big | Первый шаг на 5 минут | Запиши самое первое физическое действие: открыть файл, написать одно предложение, найти одну ссылку. Не решение — только вход. | поле → `task.fs`; кнопка «Сохранить и разгон 10 мин» |
| `warmup` | поведенческая активация | boring, tired, big | Только 10 минут | Договорись с собой на 10 минут. После можно честно остановиться — но обычно не хочется. | «Разгон 10 мин» |
| `if_then` | implementation intentions | unclear, boring, external | План «если — то» | Привяжи начало к ситуации: «Когда ___, я ___». Чем конкретнее ситуация, тем лучше срабатывает. | поля «Когда» + время → `task.cue/cueAt`, «то» = первый шаг |
| `shrink` | решение проблем | big | Уменьшить задачу | Какая самая маленькая версия ещё считается шагом вперёд? Её — первой. | поле → новая задача на 1 помидор наверх «Сегодня», та же категория |
| `thought` | когнитивная реструктуризация (КПТ) | perfect, big, pointless | Проверить мысль | Мысль — это гипотеза, не факт. Что ты знаешь наверняка? Как сказать точнее? | 3 поля: мысль / что известно / как точнее → эпизод; ✨ ИИ-подсказка; потом «Разгон 10 мин» |
| `defuse` | ACT: разделение с мыслью, готовность | perfect, boring | Взять чувство с собой | Скажи себе: «Я замечаю мысль, что…». Не надо ждать, пока станет не страшно, — возьми это чувство с собой на 10 минут. | «Разгон 10 мин» |
| `value` | ACT: ценности | pointless | Зачем это мне | Показывает «Зачем» направления задачи. Нет направления: «Эта задача не про твои цели. Может, ей место во „Входящих“?» | «Разгон 10 мин» / «Во „Входящие“»; пустое «Зачем» — поле, сохраняется в направление |
| `rest` | восстановление | tired | Честный отдых | 10 минут без экрана: вода, окно, пройтись. Потом — разгон. | «Отдых 10 мин» (перерыв), после него уведомление «Разгон?» |
| `remove_cue` | контроль стимулов | external | Убрать раздражитель | Закрой вкладку, телефон экраном вниз или в другую комнату. Мысль, которая отвлекла, — во «Входящие». | поле «во Входящие» (необязательно) + «Продолжить» |

### 4.3 Как выбирается рекомендация

```
кандидаты = способы, у которых в «Для причин» есть выбранная причина
если идёт эксперимент недели и его способ среди кандидатов → он первый
иначе сортировка по (успехи + 1) / (попытки + 2) за всё время, при равенстве — порядок таблицы
```

Попытка — эпизод с этим способом. Успех — §2. Сглаживание +1/+2 даёт новым
способам шанс и не делает вывод из одного случая.

## 5. Метрики (всё вычисляется, ничего не хранится)

| Метрика | Формула | Лучше, когда | Нет данных |
|---|---|---|---|
| **Первый помидор** | Есть `sessionWindows`: среднее max(0, старт первого помидора − начало первого окна), мин. Нет: средний час старта первого помидора | меньше | дней с помидорами < 3 |
| **Простой** | средний `delayMinutes` по помидорам, кроме первого за день | меньше | помидоров < 5 |
| **🐸 первой** | дни, где первый помидор — 🐸 / активные дни, % | больше | активных дней < 3 |
| **Переносы** | эпизоды источника «перенос» за неделю | меньше | — (0 — тоже значение) |
| **Отвлечения** (Windows) | доля секунд помидоров в отвлекающих окнах, % (`activity.json`, локально) | меньше | нет трекера |
| **Успех способов** | успехи / эпизоды со способом, % | больше | эпизодов со способом < 3 |

Неделя = спринт (пн–вс, логические сутки 05:00). Базовая неделя = неделя наблюдения.

Вердикт эксперимента: метрика лучше базы на ≥15% → «работает», хуже на ≥15% →
«хуже», иначе «без разницы». Меньше 3 дней данных → «мало данных». Пользователь
может поправить.

Метрика для правила эксперимента: `first_step`, `if_then` → первый помидор;
`warmup`, `defuse`, `rest` → простой; `shrink`, `thought`, `value` → успех способов;
`remove_cue` → отвлечения (Windows) или успех способов.

## 6. ИИ: DeepSeek V4.1 Flash

Проверено по докам DeepSeek (2026-11-04):
- `POST https://api.deepseek.com/chat/completions`, `Authorization: Bearer <ключ>`, формат OpenAI.
- Модель **`deepseek-flash`** — это и есть DeepSeek-V4.1-Flash-1017. Строка
  `deepseek-v4.1-flash` — имя у агрегаторов (OpenRouter), у DeepSeek напрямую — нет.
  Старое `deepseek-v4-flash` принимается и идёт туда же.
- Thinking включён **по умолчанию**. Для наших коротких ответов выключаем:
  `"thinking": {"type": "disabled"}` — быстрее и дешевле.
- JSON: `"response_format": {"type": "json_object"}`, в промте обязательно слово
  «json» и пример. Ответ может прийти **пустым** при `finish_reason: stop` → один повтор.
- Цена: $0.15 / 1M токенов на вход, $0.6 на выход (вне пика). Недельный разбор
  ≈ 4k токенов ≈ $0.001.

Модель — поле в настройках со значением `deepseek-flash` по умолчанию: имена у DeepSeek
уже менялись.

### Три вызова, и больше никаких

| Вызов | Где | Вход | Выход (JSON) | Без ИИ |
|---|---|---|---|---|
| `firstSteps` | ✨ в поле «Первый шаг» (лист эпизода, редактор задачи) | задача, категория, направление → веха, причина, мысль | `{"steps": [3 строки ≤80 симв.], "concern": bool}` | кнопки ✨ нет |
| `reframe` | ✨ в способе «Проверить мысль» | мысль, причина, задача | `{"pattern": id, "question": str, "alternative": str ≤140, "concern": bool}` | поля пустые, подсказки-плейсхолдеры |
| `weeklyReview` | Разбор → «✨ Разбор от ИИ» | агрегаты недели (§5), причины, способы, самочувствие, эксперимент, до 20 мыслей из эпизодов | `{"summary": str, "patterns": [{"text","evidence"}] ≤3, "experiment": {"strategy": id, "metric": id, "hypothesis": str}, "concern": bool}` | предложение эксперимента по правилу §5 |

`pattern` ∈ `all_or_nothing, catastrophizing, should, mind_reading, discounting,
overgeneralizing, none` → подписи в strings.

**Ответ проверяется кодом:** id способа и метрики должны быть из списков,
строки обрезаются по длине, лишние поля выбрасываются. Не прошло — запасной вариант.

`concern: true` (модель увидела признаки тяжёлого состояния) → вместо ответа
статичный текст: «Похоже, сейчас тяжело не с задачей. Об этом стоит поговорить
с близким человеком или специалистом». Подсказки не показываются.

Что уходит в API: только перечисленное в таблице. Никогда — заголовки окон,
заметки «на чём встал», ключи. Перед первым вызовом — одноразовое предупреждение
«Текст задачи и мысли уйдут в DeepSeek (Китай). Продолжить?».

Ключ хранится в `settings.json` в AppData (как токен Telegram), в синк не едет —
на телефоне вводится отдельно.

## 8. Данные (data.json)

Всё — дописывание существующих секций, новых верхнеуровневых ключей нет.

```jsonc
"todo": [{ "id": "…", "desc": "…", "fs": "Открыть dashboard → Webhooks",
           "cue": "сяду после завтрака", "cueAt": "09:30", "df": 2 }],
"days": { "2026-11-04": {
  "s":  [{ "id": "…", "t": "09:42", "tid": "<id задачи>" }],
  // src: idle | stop | defer | frog | distract | manual; enum хранится по name
  "e":  [{ "id": "…", "t": "10:15", "src": "idle", "tid": "…", "d": "Подключить…",
           "c": "оплата", "cause": "unclear", "st": "firstStep",
           "th": "надо сразу правильно", "fact": "…", "alt": "…", "app": "YouTube" }],
  "ck": { "sl": 4, "en": 3, "md": 4 },
  "ips": [3,4,2,3,3,2,4,3,3]
}},
"sprints": { "2026-W45": {
  "exp": { "h": "Если у 🐸 есть первый шаг…", "st": "firstStep", "m": "firstStart",
           "base": 48.0, "v": "works" },
  "ai":  { "at": "2026-11-10T09:12", "summary": "…", "patterns": [ … ] }
}},
"dirs": [{ "id": "…", "why": "свобода работать на себя" }]
```

Слияние (`data_merge.dart`):
- `e` — объединение по id внутри дня, как `s`. Удалённые эпизоды — через `graves`, `_purge` чистит и `e`.
- `ck` — по полям: `{...проигравший, ...победитель}`: утро на телефоне + вечер на ПК не теряются.
- `ips` — у победителя, если есть, иначе у проигравшего.
- `exp`, `ai` у спринта — уже покрыто `{...l, ...w}`.
- поля задач, `tid`, `why` — уже покрыто слиянием записей по id.

**Ловушка, из-за которой нужны атомарные методы:** `saveDay` пишет день целиком
снимком вызывающего. Если эпизоды писать через него, эпизод, созданный
детектором, затрётся правкой журнала, сделанной секундой раньше. Поэтому:
`addEpisode / updateEpisode / deleteEpisode / setCheckIn / saveIps` — свои методы
репозитория внутри `_serial`, а `saveDay` **сохраняет** хранимые `e/ck/ips`, а не
берёт их из снимка.

## 9. Порядок задач

```
P00  закоммитить текущий канбан (пользователь) — те же файлы, иначе конфликты
 │
P01  модель: поля задачи/помидора/направления           [Sonnet]
P02  модель: эпизоды, самочувствие, IPS, эксперимент    [Opus]   ← синк
P03  метрики недели (чистые функции)                    [Sonnet]
P04  причины и способы: константы, рекомендация, тексты [Sonnet]
P08  разгон, отдых, план старта, FirstStepField          [Sonnet]  ← можно сразу после P01
P05  InsightCubit + проводка в main                     [Sonnet]
P06  детекторы сигналов                                 [Opus]   ← таймеры, Windows/Android
P07  Лист эпизода + встраивание в таймер/стоп/задачи    [Sonnet]  ← нужны P04, P05, P06, P08
P09  Карточка дня                                       [Sonnet]
P10  экран «Разбор» + эксперимент + IPS + Спринт         [Sonnet]
P11  DeepSeek: сервис, настройки, три вызова            [Opus]   ← промты, проверка ответа
P13  окна задачи + «что было вместо»                     [Sonnet A / Opus B]
P14  окно помощи + путь внедрения + генерация доки      [Sonnet]
P12  «Зачем», README, CHANGELOG — последней              [Sonnet]
```

**Исполнители через OMC** (`omc_start`, `write: true`): «Opus» в файлах задач →
`gpt-6.1-sol` (variant high), «Sonnet» → `gpt-6.1-terra` (variant high). Исключение:
P07 (большой лист с десятком действий) — тоже `gpt-6.1-sol`. Одновременно не больше
двух задач; параллельно только P02 ∥ P08 и в отдельном worktree — иначе `flutter test`
одного агента ловит недописанные файлы другого.

P13 часть A (окна задачи по уже записанным данным) не зависит от ИИ и Разбора-недели —
её можно взять сразу после P05, если хочется увидеть результат раньше.

Параллельно можно: P08 — с P02…P05 (разные файлы). Всё остальное — по порядку:
P06, P07, P09 трогают `timer_screen.dart`, `main.dart`, `tasks_cubit.dart`.
Модель указана в каждом файле задачи. Opus — там, где ошибка тихо теряет
данные или срабатывает не вовремя.

Каждая задача: `flutter analyze` чисто, `flutter test` зелёный, коммит не делать —
ревью после каждой.

## 10. Чего сознательно нет

- **Свободного чата с ИИ.** Ни одно исследование не подтвердило безопасность
  свободных LLM-консультантов. Сценарий + слоты — как в Moa.
- **Отдельного «режима программы на 4 недели».** Неделя наблюдения
  вычисляется, дальше — недельный цикл эксперимент → разбор.
- **Корреляций и p-значений.** На 7–28 точках это шум. Разбиение «хорошие/плохие
  дни» с порогом ≥3 дней в группе.
- **Эмоции отдельным выбором.** Причины их уже покрывают; лишний тап убивает привычку.
- **Метрик в «Статистике».** Одно место — «Разбор».
- **Геймификации и свайп-тренировок (MT-PRO).** Слабая доказательная база.
